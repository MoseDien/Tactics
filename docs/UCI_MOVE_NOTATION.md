# UCI Move Notation 简介

UCI move notation 是一种简洁、适合程序处理的国际象棋着法表示方式。DailyTactics 的题目使用 `moves` 数组保存 UCI 着法序列，并结合 `fen` 指定的初始局面还原解题过程。

## 基本格式

一手普通着法由起点格和终点格直接拼接而成：

```text
e2e4
│ │
│ └─ 终点格 e4
└─── 起点格 e2
```

每个棋盘格由纵线 `a` 到 `h` 和横线 `1` 到 `8` 组成，因此普通 UCI 着法通常包含 4 个字符。

## 常见着法

| 场景 | UCI | 含义 |
|---|---|---|
| 兵向前移动 | `e2e4` | 棋子从 e2 移动到 e4。 |
| 棋子移动 | `g1f3` | 棋子从 g1 移动到 f3。 |
| 吃子 | `e4d5` | e4 的棋子移动到 d5，并吃掉 d5 上的棋子。 |
| 白方王翼易位 | `e1g1` | 白王从 e1 移动到 g1；车的移动由规则自动完成。 |
| 白方后翼易位 | `e1c1` | 白王从 e1 移动到 c1。 |
| 黑方王翼易位 | `e8g8` | 黑王从 e8 移动到 g8。 |
| 黑方后翼易位 | `e8c8` | 黑王从 e8 移动到 c8。 |
| 吃过路兵 | `e5d6` | 兵从 e5 移动到 d6；被吃的兵不在终点格。 |

UCI 不额外标记吃子、将军或将死。这些信息需要结合当前棋盘局面和国际象棋规则判断。

## 升变

兵升变时，在起点格和终点格之后追加一个小写棋子字符：

```text
e7e8q
    └─ 升变为后
```

| 字符 | 升变棋子 |
|---:|---|
| `q` | 后（Queen） |
| `r` | 车（Rook） |
| `b` | 象（Bishop） |
| `n` | 马（Knight） |

例如，`a2a1n` 表示 a2 的兵移动到 a1，并升变为马。升变着法包含 5 个字符；即使升变为后，也不能省略最后的 `q`。

## UCI 与 SAN 的区别

SAN（Standard Algebraic Notation，标准代数记谱）更接近人类棋谱的写法：

| 含义 | UCI | SAN |
|---|---|---|
| 兵从 e2 到 e4 | `e2e4` | `e4` |
| 马从 g1 到 f3 | `g1f3` | `Nf3` |
| e4 的兵吃 d5 | `e4d5` | `exd5` |
| 白方王翼易位 | `e1g1` | `O-O` |
| e7 到 e8 升变为后并将军 | `e7e8q` | `e8=Q+` |

UCI 不包含棋子名称、`x`、`+`、`#` 或 `O-O` 等符号。要判断一手 UCI 着法是否合法，必须知道执行该着法之前的局面。

## 在 DailyTactics 中的使用

题目数据示例：

```json
{
  "fen": "r3k2r/p1pp1p1p/b1p3p1/3nP3/1bP5/NP6/P3QPPP/R3KB1R w KQkq - 1 1",
  "moves": ["e1d1", "d5c3", "d1c2", "c3e2"]
}
```

执行顺序如下：

1. 使用 `fen` 创建题目的初始棋盘局面。
2. App 自动执行 `moves[0]`，即 Lichess puzzle line 的 setup move。
3. 用户从 `moves[1]` 开始作答。
4. 后续着法由用户和机器交替执行，直到数组结束。

在上面的例子中，App 先自动执行 `e1d1`，用户需要找到 `d5c3`，然后机器执行 `d1c2`，最后用户执行 `c3e2`。

## 常见检查

- 普通着法必须是 4 个字符，升变着法必须是 5 个字符。
- 起点格和终点格都必须位于 `a1` 到 `h8` 之间。
- 升变字符只能是小写的 `q`、`r`、`b` 或 `n`。
- UCI 字符串格式正确不代表着法合法；合法性取决于当前局面和行棋方。
- 数组中的每一手都基于前一手执行后的局面，不能随意交换顺序。
- FEN 描述初始局面，UCI `moves` 描述从该局面开始的着法。

FEN 格式说明请参阅 [`FEN_FORMAT.md`](FEN_FORMAT.md)。
