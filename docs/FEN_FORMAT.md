# FEN 格式简介

FEN（Forsyth-Edwards Notation）用于用一行文本描述国际象棋在某一时刻的完整局面。DailyTactics 的每道题使用 `fen` 保存初始局面，再按照 `moves` 中的 UCI 着法推进解题过程。

## 六个字段

一条完整的 FEN 由 6 个以空格分隔的字段组成：

```text
r3k2r/p1pp1p1p/b1p3p1/3nP3/1bP5/NP6/P3QPPP/R3KB1R w KQkq - 1 1
```

| 序号 | 示例值 | 含义 |
|---:|---|---|
| 1 | `r3k2r/.../R3KB1R` | **棋盘布局**：从第 8 横线到第 1 横线、每条横线从 a 文件到 h 文件书写，横线之间用 `/` 分隔。 |
| 2 | `w` | **当前行棋方**：`w` 表示白方，`b` 表示黑方。 |
| 3 | `KQkq` | **王车易位权利**：`K`、`Q`、`k`、`q` 分别表示白方王翼、白方后翼、黑方王翼、黑方后翼仍可易位；没有任何权利时写 `-`。 |
| 4 | `-` | **吃过路兵目标格**：上一手兵走两格后可能被吃过路兵的目标格，例如 `e3`；不存在时写 `-`。 |
| 5 | `1` | **半回合计数**：自上一次兵移动或吃子以来经过的半回合数，用于五十回合规则。 |
| 6 | `1` | **完整回合数**：从 `1` 开始，在黑方每次走棋后加一。 |

## 棋盘布局的编码

棋子使用一个字母表示。大写是白棋，小写是黑棋：

| 棋子 | 白棋 | 黑棋 |
|---|---:|---:|
| 王（King） | `K` | `k` |
| 后（Queen） | `Q` | `q` |
| 车（Rook） | `R` | `r` |
| 象（Bishop） | `B` | `b` |
| 马（Knight） | `N` | `n` |
| 兵（Pawn） | `P` | `p` |

连续的空格用数字 `1` 到 `8` 压缩，数字表示连续空格的数量。每条横线展开后必须正好有 8 格。

例如：

```text
8/8/8/3k4/8/4P3/8/4K3 w - - 0 1
```

- `8`：整条横线都是空格。
- `3k4`：3 个空格、一个黑王、4 个空格，即黑王位于 d5。
- `4P3`：白兵位于 e3。
- `4K3`：白王位于 e1。
- `w`：轮到白方行棋。
- 两个 `-`：双方没有易位权利，也没有吃过路兵目标格。

## 在 DailyTactics 中的使用

题目数据的相关字段示例：

```json
{
  "fen": "r3k2r/p1pp1p1p/b1p3p1/3nP3/1bP5/NP6/P3QPPP/R3KB1R w KQkq - 1 1",
  "moves": ["e1d1", "d5c3", "d1c2", "c3e2"]
}
```

- `fen` 只描述题目开始时的局面，不包含解法。
- `moves` 使用 UCI 格式描述解法，不属于 FEN。普通着法形如 `e2e4`，升变还会附加棋子字母，例如 `e7e8q`。
- Lichess puzzle line 的 `moves[0]` 是机器先走的 setup move；App 自动执行这一手后，用户从 `moves[1]` 开始作答。
- FEN 的当前行棋方是执行 `moves[0]` 的一方，因此用户执其对方棋子。

UCI 着法的详细格式请参阅 [`UCI_MOVE_NOTATION.md`](UCI_MOVE_NOTATION.md)。

## 常见检查

- FEN 必须恰好包含 6 个字段。
- 棋盘布局必须包含 8 条横线，每条展开后必须是 8 格。
- 双方通常都应各有一个王。
- 当前行棋方只能是 `w` 或 `b`。
- 无易位权利或吃过路兵目标格时要写 `-`，不能省略字段。
- 修改局面后，应同步确认当前行棋方、易位权利和吃过路兵字段仍然有效。
